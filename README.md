## How to contribute

### Rules

1. One entry is one line: `- [Title](https://link) - why it helps us, 10-50 words.` Write in English.
2. Put entries about similar things next to each other. When a file has enough entries on one topic, put them under a section heading: `## Topic`.
3. No duplicate links in one file.
4. One file, 1-2 new entries per pull request.
5. Branch name: `<your-github-login>/<topic>`, for example `ana/anki`.
6. A commit message says what changed, for example `study: Add Anki` or `Add Anki to study.md`.
7. Never push to `main`. Every change goes through a pull request.

### Steps

1. Create a branch, add your entries, commit, push.
2. Open a pull request.
3. Somebody reviews it. Answer every comment: reply in its thread, or fix it with a new commit.
4. A new push removes the approves. After your last push, ask the reviewer to approve again.
5. After a human approve, the bot checks the rules. When the check `awesome-bot` is green ("You can merge now."), merge the pull request yourself.
6. Conflict? Merge `main` into your branch, resolve the conflict, push, and ask for a new approve.

### Review

- Pull requests without review: [is:pr is:open review:none](https://github.com/pe-teaching/sdt2026-awesome-list/pulls?q=is%3Apr+is%3Aopen+review%3Anone).
- Check the rules, the link, and the section. Is the entry useful? Is the description true?
- Review in the tab **Files changed**: click **+** at a line to comment; **Review changes** (or **Submit review**) to approve or request changes.
- Approve after the author answers or fixes it. You cannot approve your own pull request.
